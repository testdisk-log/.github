# TestDisk - Look at Your Disk Before You Write

## Berth

The disk is yours, and you can say what partitions used to be on it.
Anything critical is already copied, or you accept that a mistake can cost it.
You are on a second machine or a second boot if the broken disk is not the one you are running from. Repairing the disk you booted is how you lose the tool mid-write.
You have time to read the screen. This is not a click-through wizard.

## Tide

A missing drive letter after a crash or a repartition you regret is the kind of problem this tool is for.
A disk that clicks or disappears from the firmware is a hardware problem. Software will not hold it together. Copy what you can with gentler means and stop stressing it.
An encrypted partition that you cannot unlock is still encrypted after any table write. Do not look for a bypass.
A USB enclosure can hide the real sizes. If the numbers look wrong, connect the disk directly before you trust a suggestion.

## Line

Start TestDisk against the disk whose size matches the one in your hand.
Read the partitions it offers.
Compare them to your memory: the big data volume, the small system volume, the names.
If they do not match, you do not write. You quit.

## Fender

A write is a separate confirmation. Do not confirm because the menu is highlighted.
A log file from the session is useful. Save it somewhere that is not the damaged disk.
Photograph the model and the size so the next attempt, if you need one, is on the same drive.
Stop after one careful look if you are tired. A second guess at midnight is how the wrong table gets written.

## Current

If the list matches, and the backup exists, the write is the recovery of the table, not of every file.
After a write, reboot or rescan and see whether the volume mounts.
Open a folder you remember. If the files are there, stop. Do not run a second rewrite for luck.
If the volume mounts and the files are nonsense, do not format it. Formatting throws away the chance a file carver still had.

## Do not sail

Do not point TestDisk at a disk you do not own.
Do not use it to break an encryption password.
Do not follow a video that writes a partition table without reading the sizes.
Do not run it and a benchmark on a dying disk.
Do not "repair" a healthy disk because a tutorial said everyone should.

## Return

Quit without writing if you are unsure.
The disk can go back on the shelf unplugged if it is failing. Power is stress.
A copy of any files you already rescued belongs on a different disk.
The log stays with your note, not on the damaged drive.

## Chart

Disk model and size.
Whether you wrote anything.
Whether a volume came back.
Where the rescued files are, if any.

## Not this harbor

This is not a file undelete for a single document. A carver is a different pass, and it still only belongs on a disk you own.
It is not a SMART health tool.
It is not a cloner.
It will not reconstruct a drive that is physically dead.
A cloud account is not a partition.

## Next tide

A second attempt only with the log from the first and a clear reason the first look was wrong.
A new cable or a direct port, then a new look, not a new write, if the disk was flaky.
If the files are back, you are done.
If they are not, stop guessing and treat the backup as the recovery.

## Log

You can explain the disk in one sentence.
You can say whether the table was written.
You did not format.
You did not open anyone else's drive.

## Harbor master

A shop disk gets this only from the owner, with a backup plan they agreed to.
A laptop you were lent is not your experiment.
If you cannot name the disk, you do not select it.
Uninstall changes nothing on the drive. The last write, if you made one, stays.

## Harbor line

testdisk log file, analyse only, own disk map, backup on another drive, quit without write, cylinder view, no locked volume, confirm the disk
